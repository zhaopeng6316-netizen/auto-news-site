L2 基础篇

L2-3看懂周围：感知——识别车辆、行人、车道线、红绿灯

难度：基础 阅读时间：约 11 分钟 前置知识：L2-1、L2-2 关键词：感知、检测、跟踪、车道线、红绿灯、占据栅格
导读：知道了自己在哪（L2-2），车还得知道周围有什么：前面是车还是人，车道线在哪，红绿灯是红是绿。这些任务统称"感知"，是自动驾驶最像"看懂世界"的一环。这篇讲感知系统每天在做的几件事：把图像和点云变成"框"，认出框里是什么，还要记住它下一秒仍然在。也会严肃地讲感知犯错的代价——误检和漏检都不是屏幕上的像素游戏，而是直接关系到安全的事。

一、感知的任务清单

把"看懂周围"拆开，其实是六件具体的事：

  • 检测与分类：在传感器数据里找出"这里有个东西"，并回答"它是什么"——小汽车、行人、骑车人、锥桶；
  • 多目标跟踪：记住"这就是刚才那辆车"，跨帧保持身份，得到它的轨迹和速度；
  • 车道线识别：画出本车道和相邻车道的边界，知道自己在车道里的位置和朝向；
  • 红绿灯与标志牌识别：读懂交通信号的颜色、形状和文字；
  • 可行驶空间判断：回答"哪些地方可以开"，包括没有车道线的区域（停车场、乡村道路）；
  • 速度估计：估计周围目标运动得多快，用于判断会不会撞上。

这些任务的输入是 L2-1 讲过的传感器数据——摄像头的图像、激光雷达的点云、毫米波雷达的目标列表；输出则是给下游决策规划用的结构化描述："前方 30 米有一辆同向小车，速度 60 km/h，我在车道中间，前方路口红灯。"

白话解释检测就像给画面里的每个物体"画框并贴标签"：框住它，写上"这是一辆车"。
准确定义目标检测（Object Detection）是在传感器数据（图像或点云）中定位感兴趣目标并给出类别与位置的过程，输出通常是边界框（2D 框或 3D 框）、类别与置信度（模型对"这个框里确实是车"的把握程度）。

二、从 2D 框到 3D 框：把"照片上的框"变成"世界里的框"

最早的检测是 2D 检测：在图像上画一个矩形框，框住目标。它回答"照片的哪一块像素是车"，但不回答"这辆车离我多远、多大"——照片里的小方框，可能是一辆远处的大车，也可能是一辆近处的玩具车。这就是尺度问题：单张图像丢失了深度信息。

开车却必须知道真实距离：规划模块要算"以现在的车速，几秒后会不会撞上它""要留多少跟车距离"，这些都要物理世界里的坐标。于是有了 3D 检测：输出的不是照片上的框，而是世界坐标系里的立体框——中心位置、长宽高、朝向角。

白话解释3D 检测不是在照片上画框，而是在真实的立体世界里给物体"套一个盒子"：盒子有真实的位置、大小和朝向。
准确定义3D 目标检测输出目标在物理坐标系中的三维包围框（3D Bounding Box），包含中心坐标（x, y, z）、尺寸（长、宽、高）与航向角，通常由激光雷达点云、多目视觉或多传感器数据融合得到，是下游预测与规划的直接输入。
看照片分不清远处的大楼和近处的积木模型——照片把"远近"弄丢了，2D 框也一样。3D 检测相当于给每个物体报出真实的长宽高、距离和朝向，就像把照片里的东西还原成了摆在桌上的实物模型。

深度从哪来？激光雷达的点云本身就是三维的，把点云聚成簇就是天然的 3D 框；纯视觉方案则靠双目视差、多帧运动或者"先验尺寸"来推算距离。这也是"纯视觉 vs 激光雷达"路线之争的核心之一：距离信息是量出来，还是算出来？两种路线各有支持者，本篇不下结论，L3 之后再深入。

三、多目标跟踪：让"同一辆车"不换身份

单帧检测有个根本局限：它只说"这一帧里有个东西"，不知道这个东西从哪来、往哪去、跑多快。而开车需要的恰恰是运动信息——旁边那辆车是在加速插队，还是匀速巡航？

白话解释跟踪就是给每个目标"发一个身份证号"，让它在连续的画面里一直是"它"，而不是每一帧都被当成新目标。
准确定义多目标跟踪（Multi-Object Tracking, MOT）在检测结果的基础上，通过数据关联（Data Association）维持各目标跨帧的身份（ID）与状态（位置、速度等），输出随时间连续的目标轨迹。

ID 持续性是跟踪的核心：同一辆车在连续几十帧里保持同一个编号，即使被前车短暂遮挡、从树荫下钻出来，也要"认回来"还是那辆车，而不是当成新车重新开始。这样才能得到它的完整轨迹，进而估计速度和加速度。

就像老师给每个学生发学号：学生换了座位、被桌子挡住一会儿、中途出去又回来，学号不变。有了学号，才能说清"谁去了哪里、走了多快"——跟踪给目标发的"ID"，作用和学号一样。

系统的运转方式是一个循环：每一帧先检测，再把新的检测结果和已有的轨迹关联——匹配上的更新轨迹，匹配不上的要么是新目标（给它发新 ID），要么是旧目标消失（收走 ID）。这里面的判断错不得：把两辆并排的白色轿车认成同一辆，后面的速度估计和决策就全错了。

四、车道线与可行驶区域

除了"框住物体"，感知还要回答"路在哪"。一种常用技术是语义分割：

白话解释语义分割是"给每个像素贴标签"：把整张图按用途涂成不同色块——路面一片、车道线一条、天空一块。
准确定义语义分割（Semantic Segmentation）是像素级分类任务，为图像中每个像素分配语义类别（如车道线、路面、车辆、行人、背景），常用于提取车道线与可行驶区域（Free Space）。

有了它，系统就知道"哪几个像素是车道线"，拟合出车道线的曲线，也就知道自己在车道内的横向位置和朝向。但现实中的车道线很不给面子：磨损变淡的、被前车遮住的、雨天路面反光看不清的、施工路段临时改画的，都会让识别变难。

还有一类区域根本没有车道线——停车场、小区内部道路、乡村土路。这时感知要直接判断可行驶空间："哪些地方是路面、可以开过去"，不管它有没有画线。这对自动泊车和园区通勤场景尤其重要。

五、红绿灯与标志牌识别

红绿灯是典型的"看起来简单、做起来难"的任务。难点主要有三个：

  • 逆光：太阳正好悬在信号灯背后时，图像里灯体和天空糊成一片，颜色很难分辨——人也要眯着眼看半天；
  • 异形灯：箭头灯、带倒计时数字的灯、竖排/横排组合灯、临时信号灯，形态五花八门，训练时没见过的样式就容易出错；
  • 距离与曝光：远处的灯在图像里只有几个像素，夜间灯体又可能过曝成一个亮团。

工程上的应对思路是组合拳：用高动态范围摄像头保留明暗细节，结合高精地图先验（提前知道信号灯大概在哪个位置、是哪种类型，L2-2 已经讲过地图的作用），再用专门训练的分类器识别颜色和箭头方向。标志牌识别（限速、禁止超车、施工）同理，难点在污损、遮挡和不规范的临时标牌。

六、感知错误的代价

这一节要严肃地说：感知输出直接决定车的刹车和转向，错误分两种，代价都很实在。

误检（把没有的东西当成障碍物）：把路面的塑料袋、井盖反光、桥影当成障碍物，系统可能触发急刹——高速上毫无预兆的急刹（常被称为"幽灵刹车"）可能让后车追尾，同样危及安全。

漏检（把有的东西看漏）：没看见障碍物，意味着不会减速、不会避让，直接导致碰撞，后果往往比误检严重得多。

行业长期公开讨论的两类经典难点可以说明问题的棘手：静止的白色大货车横在车道上——车身白色与明亮的天空/背景在图像里融为一体，而毫米波雷达又常把静止物体当杂波滤掉；侧翻或掉落货物的车辆——形状不属于训练时的常见类别，"这是什么、在哪"都难以判断。多年来多起辅助驾驶相关事故的公开报道与讨论都涉及静止车辆、施工区等场景（具体事故原因与责任认定，以官方调查结论为准，本篇不做推断）。这些不是遥远的理论问题，而是感知系统每天要面对的考题。

由此得出一条工程共识：感知要"宁可误报、不可漏报"。误检可以由下游降级处理（再确认、平缓减速），漏检却没有挽回机会；而要压住漏检，就要靠多传感器冗余与融合（L3-2）互相补位。

七、感知进阶预告：BEV 与占据栅格

近年感知有两个重要方向，这里先给概念，不展开：

白话解释占据栅格像把周围空间切成无数个小格子，每格标明"这里有东西"还是"这里空着"。
准确定义占据栅格（Occupancy Grid，常缩写 OCC）将车辆周围的空间离散化为网格（或三维体素），逐格估计被占据的概率，从而统一描述任意形状的障碍物——包括训练中没见过的异形物体。

另一个方向是 BEV（Bird's Eye View，鸟瞰视角）：把多个摄像头、激光雷达的视角统一转换成"从天上往下看"的一张图，所有目标在同一坐标系里表述，跨传感器不再各说各话。BEV 与占据栅格如何构建、如何与时序信息结合，是 L3-1 的主题。

本篇小结

  • 感知的任务清单：检测分类、多目标跟踪、车道线、红绿灯与标志牌、可行驶空间、速度估计。
  • 2D 检测只给"照片上的框"，3D 检测给出真实坐标、尺寸和朝向，才能支撑规划决策。
  • 跟踪给目标发"ID"，保持跨帧身份连续，得到轨迹和速度。
  • 车道线靠语义分割等技术提取；红绿灯识别难在逆光、异形灯和远距小目标。
  • 误检会造成急刹风险，漏检直接导致碰撞；感知宁可误报不可漏报，靠融合补位。

自测题

1.（单选）3D 检测与 2D 检测的核心区别是什么？
A. 3D 检测用的摄像头更多　B. 3D 框包含真实坐标、尺寸和朝向，2D 框只有图像像素位置　C. 2D 检测更慢　D. 3D 检测不需要训练数据
查看答案
B。2D 检测输出图像上的矩形框，不包含真实距离与大小；3D 检测输出物理坐标系中的立体框（位置、长宽高、航向角），直接供规划使用。
2.（单选）多目标跟踪主要解决什么问题？
A. 识别红绿灯颜色　B. 让同一目标在连续帧中保持同一身份，得到连续轨迹和速度　C. 提高摄像头曝光　D. 压缩点云数据
查看答案
B。跟踪通过数据关联维持目标跨帧的 ID（身份持续性），输出连续轨迹，才能估计速度、加速度并预测下一步动向。
3.（判断）感知系统"漏检"一个静止障碍物的风险，比"误检"把塑料袋当障碍物更低。
查看答案
错误。漏检意味着系统不知道障碍物存在，不会减速避让，直接导致碰撞；误检最多引发不必要的减速或急刹。因此感知设计强调宁可误报、不可漏报。
